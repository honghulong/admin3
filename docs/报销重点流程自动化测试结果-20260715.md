## 缺陷记录

### BUG-REIM-001：删除已关联发票后费用明细金额未重算

严重级别：高

关联用例：`TC-016`

关联脚本断言：

```js
assert(afterDeleteExpenseTotal === expectedAfterDelete, `expense total should decrease to ${expectedAfterDelete}, got ${afterDeleteExpenseTotal}`);
```

复现步骤：

1. 新建草稿报销单。
2. 上传两张有效发票。
3. 新增一条费用明细，并关联两张发票。
4. 保存费用明细，主表金额和费用明细金额均为 `336.90`。
5. 删除其中一张已关联发票，删除发票金额为 `148.00`。
6. 查询报销单详情。

期望结果：

- 被删除发票不再出现在有效发票列表。
- 主表 `invoiceCount` 从 2 变为 1。
- 主表 `invoiceTotalAmount` 从 `336.90` 变为 `188.90`。
- 费用明细对该发票的包含关系解除。
- 费用明细金额从 `336.90` 重算为 `188.90`。
- 主表 `amount` 应同步为 `188.90`。

实际结果：

- 有效发票列表只剩 1 张，通过。
- 主表 `invoiceCount = 1`，通过。
- 主表 `invoiceTotalAmount = 188.90`，通过。
- 费用明细 `invoiceIds = [9]`，显示只剩一张发票，通过。
- 费用明细 `invoiceTotalAmount = 188.90`，通过。
- 费用明细 `amount = 336.90`，失败。
- 主表 `amount = 336.90`，失败。

当前数据摘录：

| 字段 | 实际值 |
|---|---:|
| `reimbursement.id` | `19` |
| `reimbursement.invoiceCount` | `1` |
| `reimbursement.invoiceTotalAmount` | `188.90` |
| `reimbursement.amount` | `336.90` |
| `expenseItems[0].invoiceIds` | `[9]` |
| `expenseItems[0].invoiceTotalAmount` | `188.90` |
| `expenseItems[0].amount` | `336.90` |

初步判断：

删除发票时，后端已将发票软删除并解除发票侧 `expenseItemId`，主表发票数量和发票合计也已正确重算；但未按剩余有效发票重新计算受影响费用明细的 `amount`，导致费用明细金额和主表报销金额仍保留删除前金额。

建议修复方向：

- 在删除发票逻辑中，记录被删除发票原所属费用明细 ID。
- 删除后按该费用明细当前剩余有效发票重新计算明细金额。
- 如果该费用明细不再包含任何发票，可按业务规则置 0、保留手工金额或提示用户确认；当前测试方案建议置为剩余关联发票合计。
- 最后调用主表汇总重算，确保 `amount`、`invoiceCount`、`invoiceTotalAmount` 一致。

## 本轮结论

本轮自动化已成功覆盖新建、上传发票、OCR 生成发票、多发票关联费用明细、主表金额优先明细合计等关键路径；在删除已关联发票后发现汇总联动缺陷。该问题会直接影响报销金额准确性，应优先修复后再次执行本测试脚本。
