# 报销业务重点流程测试方案

## 目标

本文档记录报销业务的正常操作流程、重点自动化测试用例，以及用例与真实发票测试数据的对应关系。第一阶段优先覆盖高风险链路：报销单主表、发票上传识别、费用明细、发票关联、删除后的上级汇总字段联动。

## 资料性质

- 业务对象：企业费用报销业务管理系统。
- 测试数据：真实清晰发票样本，位于 `docs/xlf/organized`。
- 自动化脚本：`tests/reimbursement-critical-flow.playwright.js`。
- 执行方式：默认通过本地/测试环境 API 自动化执行，不在本文档生成时实际执行。

## 关键假设

- 测试环境允许使用真实发票样本做识别测试。
- 执行自动化时提供可登录账号，且该账号拥有 `reimbursement:create/update/view/delete/submit` 等权限。
- OCR 服务可用时，上传附件会异步生成发票记录；OCR 不可用时，相关用例应失败并暴露环境问题。
- 自动化脚本会创建测试报销单，适合在测试环境执行；不要直接在生产环境执行。

## 正常操作流程

1. 操作人员登录系统，进入报销列表。
2. 在列表中按状态、关键字查询报销单，查看发票数、发票合计、报销金额、状态等字段。
3. 新建报销单，填写报销标题、报销金额、报销事项详细描述。
4. 上传发票或凭证文件，等待附件 OCR 状态从 `pending/processing` 变为 `completed/failed`。
5. OCR 成功后，系统生成发票记录，并更新报销单发票数、发票合计、OCR 原始 JSON 和识别说明。
    （系统自动尽可能根据发票类型将发票归类关联到费用明细当中，不能归类的让用户手动处理）
7. 操作人员检查、编辑或删除发票数据。
8. 操作人员新增费用明细，填写日期、费用类型、始发、终点、备注等信息。
9. 在费用明细中关联发票。关联后费用明细金额等于已关联发票合计；取消关联后重新计算。
10. 保存报销单。后端保存费用明细时会先清空该报销单原有明细和发票关联，再按当前数据重建。
11. 草稿报销单提交后进入待审批；待审批可审批通过、退回或撤回。
12. 可导出电子发票登记表、报销费用明细表，或批量导出 OA 报销包。

## 汇总联动规则

- 发票新增：`invoiceCount` 增加，`invoiceTotalAmount` 累加。
- 主表报销金额：`amount = invoiceTotalAmount`，始终按有效发票合计汇总。
- 费用明细金额仅用于分类、行程、关联和校验，不反向更新主表报销金额。
- 费用明细关联发票：明细金额等于关联发票 `totalAmount` 合计。
- 发票删除：发票软删除，解除 `expenseItemId` 和费用明细对该发票的包含关系，重新计算费用明细金额，并重新计算主表发票数、发票合计、报销金额。
- 费用明细删除：明细移除，其关联发票应回到未关联状态，主表金额重新计算。
- 保存费用明细：旧明细不应残留，发票绑定应按最新 `invoiceIds` 重建。

## 重点自动化用例

| 用例编号 | 名称 | 自动化覆盖 | 测试数据 | 关键断言 |
|---|---|---|---|---|
| TC-001 | 新建草稿报销单 | 是 | 无 | 创建成功，状态为 `draft`，申请人为当前用户 |
| TC-007 | 上传单张有效发票 | 是 | INV-VAT-001 | OCR 完成后至少生成 1 条发票，发票数和发票合计更新 |
| TC-008 | 上传多张发票 | 是 | INV-VAT-001、INV-VAT-002 | 发票数量增加，发票合计等于有效发票金额合计 |
| TC-009 | 上传重复发票 | 预留 | INV-DUP-001 | 发票数和合计不应重复累加，或按系统规则合并/提示 |
| TC-020 | 一条费用明细关联一张发票 | 是 | INV-VAT-001 | 明细金额等于发票金额，发票绑定到该明细 |
| TC-021 | 一条费用明细关联多张发票 | 是 | INV-VAT-001、INV-VAT-002 | 明细金额等于两张发票合计，主表金额仍等于有效发票合计 |
| TC-015 | 删除未关联发票 | 部分 | 已上传发票 | 发票软删除，主表发票数/合计重新计算 |
| TC-016 | 删除已关联发票 | 是 | 已关联发票 | 发票软删除，费用明细金额扣减，主表汇总扣减 |
| TC-019 | 删除费用明细 | 是 | 已有关联明细 | 明细不存在，发票解除关联，主表金额回退 |
| TC-028 | 无费用明细时金额回退发票合计 | 是 | 已上传发票 | 删除所有费用明细后 `amount = invoiceTotalAmount` |
| TC-029 | 有费用明细时主表仍按发票合计 | 是 | 已上传发票 | `amount = invoiceTotalAmount`，不被费用明细手工金额覆盖 |
| TC-030 | 提交草稿 | 是 | 已创建报销单 | 状态从 `draft` 变为 `pending`，生成提交日志 |
| TC-041 | 既有手工费用明细自动关联新增识别发票 | 是 | INV-DIDI-001 | 已存在手工“网约车费”明细时，后续上传/识别出的网约车发票应自动绑定到该明细；明细金额同步发票，主表金额按有效发票合计 |

## 自动化执行说明

脚本位置：

```bash
tests/reimbursement-critical-flow.playwright.js
```

推荐命令：

```bash
npm run test:reimbursement:critical
```

必要环境变量：

```bash
ADMIN3_BASE_URL=http://localhost:9099/admin3
ADMIN3_USERNAME=admin
ADMIN3_PASSWORD=123456
```

可选环境变量：

```bash
ADMIN3_OCR_TIMEOUT_MS=180000
ADMIN3_TEST_TITLE_PREFIX=自动化报销重点链路
```

## 验收标准

- 文档中的重点用例均有明确编号。
- 自动化脚本输出中包含对应用例编号。
- 自动化脚本使用 `docs/xlf/organized` 下的真实清晰发票。
- 自动化脚本不会硬编码账号密码。
- 汇总字段重点断言覆盖 `amount`、`invoiceCount`、`invoiceTotalAmount`、`expenseItems[].amount`、`invoices[].expenseItemId`。
